Date: 2026-08-21

Scope: prepare the software evidence needed for the BRISK-KV paper. This file
does not change algorithm code, RTL, or frozen hardware artifacts.

## 1. S0 Frozen-Baseline Guardrails

Paper claim being supported:

- The software baseline work supports the algorithm/format viability claim:
  `FP -> original/continuous PackKV -> PO2 + NONE -> PO2 + BUCKET`.
- It does not support any GPU speedup, end-to-end energy, full-system, or
  physical-signoff claim.

Frozen hardware boundary to preserve:

- Retained point: `shared_writer_cg_v1`
- Top: `BriskKvSharedJitVWriterCgSingleHeadTileTop`
- Primary frozen geometry: 1024 tokens x 128 features, 2.0 ns / 500 MHz
- Frozen directories that must not be overwritten:
  - `hardware/evaluation/results/cycle_breakdown/2026081703_shared_writer_cg/`
  - `hardware/simulation/results/2026081801/`
  - `hardware/synthesis/dc/results/2026081801/`
  - `hardware/synthesis/dc/results/2026081802/`

Result-management rule for new software experiments:

- Use timestamped roots under `eval_logs/`, `logs/`, and `csv_results/`.
- Preserve model name, task, limit, batch size, quant parameters, scale method,
  repack method, block/buffer/pack size, bucket parameters, software versions,
  and exact output paths.
- Every row used in a paper table must be generated from a machine-readable
  CSV/JSON summary, not copied from terminal output.
- Existing `docs/MY_IDEAS.md` software numbers remain preliminary unless their
  original experiment directories and FP baseline provenance are recovered.

## 3. Available Script Entry Points

### Accuracy

| Script | Purpose | S1 relevance |
|---|---|---|
| `scripts/accuracy/accuracy_eval.py` | Main accuracy CLI. Supports `--no_quant`, `--scale_method`, `--repack_method`, `--k_scale`, `--v_scale`, `--block_size`, `--buffer_size`, `--pack_size`, and bucket settings. Emits `results.json`, `packkv_config.json`, and samples when `-o` is set. | Primary S1 accuracy runner. |
| `scripts/accuracy/summarize_pa_accuracy.py` | Recursively reads `results.json` plus sidecar `packkv_config.json` and emits a stable accuracy summary CSV. | Required for paper table generation. |
| `scripts/accuracy/compare_repack_accuracy.py` | Pairs `NONE` and `BUCKET` accuracy runs and emits paired comparison. | Useful for PO2+NONE vs PO2+BUCKET accuracy delta. |
| `scripts/accuracy/run_pa_accuracy.sh` | Existing broad runner for FP, continuous, nearest, and packing-aware variants. | Useful as a reference, but it does not exactly match the retained PO2+BUCKET S1 matrix. |
| `scripts/accuracy/run_repack_accuracy_validation.sh` | Runs `po2_nearest` NONE/BUCKET pairs, default model `NousResearch/Meta-Llama-3.1-8B`, default limit 200. | Good pilot for paired repack accuracy. |
| `scripts/accuracy/run_scale_sensitivity.sh` | Runs Qwen3-4B/Qwen3-8B FP plus continuous/po2 scale sweep with default limit 200. | Useful pilot evidence, not final S1. |
| `scripts/accuracy/run_nearest_full_validation.sh` | Runs Llama-3.1-8B full GSM8K nearest/continuous candidate rows. | Useful for Llama branch of S1, but does not cover Qwen models by default. |
